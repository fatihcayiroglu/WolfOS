# ADR-0107 — Authenticated real-PMM source pixels in QEMU composition

Status: proposed; draft stacked after PR #334 / ADR-0106.

## Scope

Previous QEMU proof (#334) allocated real physical PMM frame leases to two
`ProcessTable` owners, but exercised only metadata-based surface retirement.
This incremental test now **writes and reads actual bytes in the two
process-owned PMM data frames** and uses those slices as independent source
pixels through `compose_registered`.

Two separate READY PIDs each reserve a private two-frame PMM lease.
The kernel-only QEMU fixture reads the Limine-provided HHDM offset and
derives canonical HHDM addresses from the *second* page of each lease.
Each source has four distinct 32-bit xRGB8888 pixel words, written through
the real mapped physical RAM and then read by a scoped immutable Rust slice.
The first frame of each process lease, its CR3-root *metadata*, is not
modified. There is no Ring3 mapping or new memory allocation inside the
pixel composer.

The software viewport is 8x8. Two 2x2 rectangles overlap by two pixels.
The exact expected pixel proof is:
- First owner only: 2 pixels
- Front owner: 4 pixels
- Background: 58 pixels
- Full scan: all 64 output words match their unique expected source
- No mutation on forged PID generation or invalid z-order
- After `cancel_ready_counted_guarded` closes owner A while the synthetic
  GPU transfer is still pending, the same real physical source slice remains
  readable but **the compositor must reject every write**. The entire
  destination buffer retains its sentinel value.

All scopes containing references to the actual PMM frame pixels must end
before returning any physical frame to the PMM. Only the original guarded
PMM retirement path frees those pages, after explicit logical GPU fence
drain (synthetic in this particular test) and exact handle release.

The QEMU serial proof now includes
`owner_pixel_composition=1 stale_owner_pixels_denied=1`.
The existing P0 QEMU job enforces the complete marker exactly once and
retains the previous genuine PMM accounting and real GPU regression steps.

## Nonclaims

- The source pages are **kernel-accessed HHDM physical RAM**, legitimately
  reserved by the two `ProcessTable` owners. They are not writable
  userspace-mapped buffers and no Ring3 application supplied the pixels.
- The 8x8 composition is **CPU software only**. It is not submitted to
  VirtIO-GPU, scanned out, displayed or independently attested by QMP.
- The transfer and flush acknowledgements in this isolated scenario
  remain **synthetic policy inputs**; no real DMA or device response is
  generated by this new proof.
- No production syscall teardown path, SMP coordinator lock, real per-process
  page mapping or physical-GPU hardware support has been added.

Next: safely map verified user-authored backing under real Ring3 access
permissions, retain CPU references across freeze/revocation and bind a
driver-confirmed used-ring response before releasing physical frames.
Do not conflate the existing separate real VirtIO-GPU host screen tests
with this new per-process pixel ownership proof.

Keep this PR draft; do not merge into `main` until explicit authorization
and complete, exact-head P0 CI.
