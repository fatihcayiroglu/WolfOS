# WolfOS roadmap and acceptance gates

P0: Rust no_std x86-64 kernel; QEMU serial, memory-map and framebuffer smoke checks.

P1: CPUID (merged); physical frame allocator (merged), scalable HHDM-backed bitmap (merged); GDT/IDT, CPU exceptions (merged), paging map/unmap and #PF (merged), PCI read-only discovery (merged), ACPI RSDP read-only validation (merged); RSDT/XSDT checksum validation and MADT CPU count (merged), Limine AP Rust handshake (merged); AP-local GDT/TSS/IST/IDT, WolfOS-owned AP stacks and verified SMP CPU work (merged); cooperative exactly-once kernel job queue (merged); per-CPU task queues and Ready/Running/Blocked/Finished lifecycle (merged); BSP-only cooperative assembly context-switch proof (merged); three stack-backed TCB execution contexts and yield/block/wake test (merged); generic indexed 16-TCB context batch (merged); 256 BSP-owned stack-backed TCB proof with strict 4 MiB stack bank (merged); real per-CPU context switching with private kernel stacks (merged).

P2: Ring 3 user mode, syscalls, ELF loader, init, scheduler and RAM-backed file system.

P3+: graphics, audio, networking, tested driver packages, secure updates with rollback.

Windows and Steam applications are aspirational milestones: Linux ABI / POSIX, Win32/NT API compatibility, Vulkan graphics, DRM and anti-cheat restrictions. No universal compatibility promise.

No milestone can be marked complete without reproducible build and run evidence.

P1 topology validation (merged): isolated QEMU MADT tests with 1 and 4 virtual CPUs. APs execute verified Rust work on dedicated stacks, with independent GDT/TSS/IST/IDT and real per-CPU cooperative kernel context switching. APs park with interrupts disabled after the boot proof. No preemptive or fully dynamic SMP scheduler yet.

P1 legacy timer (merged): isolated single-BSP PIT/8259 IRQ0 delivery, PIC EOI and tick-gated **safe-point/cooperative** dispatch between kernel contexts in QEMU. This is not asynchronous task preemption.

P1 local APIC discovery (merged): per-CPU read-only IA32_APIC_BASE MSR and CPUID APIC-ID validation for BSP/APs; temporary, read-only uncached BSP xAPIC MMIO mapping for ID/version observation. Normal kernel boot still does not enable APIC timer IRQs.

P1 xAPIC timer hardware proof (merged, PRs #26–#31): pure LVT/divisor/vector validation, masked timer programming plan and EOI/SVR validation, plus *isolated QEMU smoke-mode* writable MMIO, genuine periodic BSP APIC timer interrupts and matching EOIs. The IRQ path passed 1- and 4-vCPU QEMU tests; no AP timer delivery is claimed. Test tears down the temporary mapping, masks LVT and leaves CPU interrupts disabled.

P1 reference calibration proof (merged, PR #32): isolated BSP PIT channel 2 terminal-count polling (~20 ms) measures the decrement of a masked xAPIC one-shot timer, then uses checked integer arithmetic to estimate a 100 Hz periodic initial count. Full QEMU acceptance verifies both calibration results and actual IRQ/EOI delivery with 1 and 4 vCPUs (Actions #213, 14 October 2026). PIT2 does not establish general-purpose clock precision, drift bounds or cross-hardware portability.

P1 xAPIC tick-gated cooperative context proof (merged, PR #34): reuse the two independent stack-backed Rust execution contexts from the PIT smoke test; each APIC timer epoch permits one voluntary yield on the BSP. Both calibrated and uncalibrated xAPIC timer QEMU smoke flavors require six strictly increasing IRQ epochs, six dispatches and twelve RSP switches on 1 and 4 vCPUs. The IRQ handler only publishes an atomic counter and EOI; **this is NOT IRQ-frame preemption**.

P1 read-only xAPIC interrupt-frame observation (merged, PR #35): an independent non-yielding BSP workload is interrupted by the xAPIC timer at least four times; the IRQ handler records a copy of its first architectural RIP/RSP/CS/RFLAGS values and the in-flight work count. The work must resume and advance after the first IRQ; 1- and 4-vCPU QEMU regressions validate the frame's CPL0, stack alignment and saved IF. **This captures no GPR/SIMD state, performs no scheduler handoff, and never restores a new context.**

P1 complete-GPR trap-frame layout preflight (merged, PR #36): fixed `repr(C)` x86-64 ring-0 frame offsets for 15 general registers and the five architectural IRQ return fields, with reject-on-invalid stack bounds, selector and IF. This is a host-tested **contract for a future assembly entry**, NOT a verified hardware handler, full processor-state save, task switch or preemptive scheduler. A real entry/exit stub, FP/SIMD state policy and QEMU involuntary handoff are still required.

P1 xAPIC assembly GPR entry/IRETQ proof (merged, PR #37): isolated QEMU APIC smoke replaces the compiler-generated x86-interrupt timer entry with a hand-written kernel-CPL0 assembly interrupt-gate stub. It pushes/pops 15 general-purpose registers in the defined trap-frame ABI, passes a temporary frame to a Rust EOI/atomic-only handler with stack realignment, and returns to the **same interrupted context** via IRETQ. Acceptance requires matched real IRQ/EOI/trap counts, non-yielding worker completion, and existing cooperative dispatch on 1- and 4-vCPU calibrated/un-calibrated QEMU. **No task involuntarily switches to another task.** Floating-point/SIMD, per-task kernel stack ownership, task-state/CR3/TLS and robust IRQ-safe dispatch are still missing.

P1 live all-GPR preservation regression (merged, PR #38): a dedicated BSP-only assembly worker loads distinct sentinels into all fifteen general-purpose registers, then performs a bounded non-yielding loop. A real local xAPIC timer interrupt must capture exactly those values in the assembly trap frame; the entry saves/restores every GPR and IRETQs to the **same** worker. Full calibrated/un-calibrated 1/4-vCPU QEMU regressions require at least four valid observations and zero mismatches, independently of the earlier read-only Rust worker frame proof. This does not prove SIMD/FPU state preservation or involuntary task handoff.

P1 isolated BSP involuntary kernel preemption proof (merged, PR #39): separate QEMU-only `apic-preempt-smoke` flavor uses the xAPIC IRQ assembly stub to store the live 15-GPR/hardware interrupt frame for one non-yielding kernel task, select another validated private-stack frame and IRETQ to the other task. The two tasks NEVER voluntarily yield to each other; they must both progress under >=8 genuine IRQ-triggered switches (>=4 interrupted epochs per task). The final running task transfers ONCE back to the BSP test harness with IF=0 for teardown. Acceptance requires 1- and 4-vCPU QEMU runs, zero rejected frame bounds/selector/IF checks and complete existing regression suite. **This is a narrow smoke proof, not a production preemptive scheduler**: task creation/destruction, SMP task queues, synchronization, user mode, kernel-stack guard pages, XSAVE/FPU/SIMD, CR3/TLS, fault recovery, arbitrary interrupt nesting and cross-CPU interrupts remain pending.

P1 IRQ-safe nested preemption-disable proof (merged, PR #40): extend the isolated BSP two-task preemptive QEMU smoke with a checked atomic preemption-disable depth (host tests for nested entry/exit, underflow and overflow). Task 0 keeps interrupts enabled inside two nested critical sections; at least four APIC timer IRQs must arrive, be EOI'd and be explicitly deferred without switching tasks. Only after the final matching enable may hardware timer IRQs switch task stacks; then both non-yielding tasks progress and the existing eight-switch acceptance passes. **This guards only BSP smoke code**, not cross-CPU locking or production scheduler critical sections.

P1 BSP legacy x87/SSE save/restore (merged, PR #41): isolated `apic-preempt-smoke` mode snapshots the original BSP FX state, sets the required x87/SSE CR0/CR4 controls after CPUID FXSR/SSE2 verification, initializes independent 16-byte-aligned 512-byte FXSAVE64 images and saves/restores task-specific state on each **real xAPIC timer-triggered task stack handoff**. Two non-cooperative tasks keep distinct XMM0 low-64-bit sentinels, verified both in running tasks and in saved FX images; the original BSP state/control flags are restored before returning from the test. Gate on 1/4-vCPU QEMU runs and zero observed corruptions. **This covers legacy x87/MMX + SSE XMM images only, not XSAVE/AVX/AVX-512 or production per-task FPU ownership.**

P1 three-way preemptive round-robin smoke (merged, PR #42): extend the isolated BSP hardware APIC preemption proof from two to three independent 16 KiB kernel stacks and three FXSAVE64 contexts. Two tasks are synthesized from validated IRETQ frames; the first enters through the existing BSP context primitive. An allocation-free bounded ready-bitmask selector rotates among all three on real timer IRQs. Require >=12 involuntary handoffs, >=4 interrupted epochs for each task, <=1 maximum difference in IRQ dispatch counts, nonzero work for all tasks, 0 rejected frames, independent XMM0 sentinels with 0 corruption, unchanged nested critical-section deferral and exactly matching IRQ/EOI counts in both 1- and 4-vCPU QEMU. **This is not yet dynamic task creation, SMP scheduling, process isolation, production run queues or XSAVE.**

P1 real blocked/wake/resume lifecycle proof (merged, PR #43): the BSP-only three-task QEMU xAPIC preemption smoke now permits task1, **while actually running**, to clear its own runnable bit in an atomic checked operation with a preemption-disabled critical section. At its next real timer IRQ, task1's work count is snapshotted and its original saved RIP/RSP/GPR/FX state is parked. Other tasks must progress while >=6 more xAPIC interrupts occur, all proving the blocked task's work count remains frozen and the scheduler skips its bit. Only a timer-driven checked wake restores task1 to Ready; it must resume exactly once on the suspended kernel stack with preserved SSE XMM0. After wake, require >=4 dispatches per each of three tasks and a round-robin fairness gap <=1, while IRQ/EOI parity and all prior tests remain mandatory in 1- and 4-vCPU QEMU. **This is fixed BSP-only lifecycle proof, not a production sleep/wakeup API, general task ownership, dynamic allocation or full SMP scheduler.**

P1 Finished task retirement under real timer IRQs (merged, PR #44): task2, running on its own BSP-private kernel stack, transitions to **Finished** after the post-wake three-task round-robin proof. It atomically clears its Ready bit and sets an independent terminal-state mask under a preemption-disabled critical section, without reusing or freeing its still-live interrupt stack. Its first subsequent xAPIC IRQ snapshots the final work count; >=6 additional IRQs must prove work remains frozen, task2 is never selected again, and tasks0/1 continue receiving >=4 IRQ-scheduled dispatches each with fairness delta <=1. Pure host tests refuse re-waking or re-finishing a terminal task, last-ready termination, invalid masks or indices. Acceptance includes original x87/SSE isolation, blocked/wake/resume checks and 1/4-vCPU QEMU. **No stack reclamation, PID reuse, dynamic task creation or true production lifecycle yet.**

P1 quiescent fixed-slot recycling proof (merged, PR #45): after the full three-task BSP preemption QEMU test and >=6 real IRQ observations that the Finished task2 never runs again, return to an independently measured **disjoint BSP stack with IF=0**. A generation-tagged task-slot owner denies early/active reclaim, stale handles, duplicate allocation and generation wrap; only verified quiescence permits task2 to move to Vacant. The old 16 KiB stack and 512-byte legacy FX image are explicitly wiped with volatile stores and read back. The FX image is reseeded from the saved valid original baseline, while the wiped stack receives a new, separately validated kernel-only IRETQ frame and a strictly newer generation. Its ready-mask bit remains **cleared**: the new occupant is initialized but NOT executed. Require this evidence in 1/4-vCPU QEMU and keep all existing Finished, Blocked/wake, SSE and IRQ/EOI regressions. **This recycles a static slot, not physically free-able pages, a general spawn API, a live recycled-task execution test or SMP-safe reclamation.**

P1 real second-generation task execution from a recycled kernel stack (merged, PR #46): After PR #45's quiescence-gated 16 KiB stack and 512-byte SSE image wipe and incremented slot generation, the **previously unqueued new kernel task is actually entered** through a dedicated BSP x86-64 assembly bootstrap. The bootstrap saves the BSP's callee-saved GPRs, restores all fifteen registers from the validated new full trap frame, and IRETQs onto the recycled stack with IF=1. An assembly entry probe records distinct new-generation R12/R15 sentinel values before any Rust prologue. The new task works without a voluntary yield and survives >=4 genuine local-APIC timer IRQs, each validated against its own stack/frame and EOI'd before IRETQ to the **same new task**. SSE XMM0 must start from the clean baseline, not the old generation's sentinel; the task sets a different marker and restores it through all interrupts. It then returns ONCE to its saved BSP context with IF=0; BSP snapshots/restores FX state and marks the new handle Finished while the **old handle remains stale**. This is a separate BSP-only **single-task direct-bootstrap epoch**; the original three-task scheduler is inactive, and **the new task is NOT yet dynamically enqueued or given IRQ-driven task-to-task scheduling**, nor are any pages freed or cross-CPU references reclaimed.

P1 real in-flight kernel task enqueue (merged, PR #47): extend the existing BSP-only three-task xAPIC preemption QEMU mode with a **fourth initially absent, separately stacked kernel task**, not run at boot. While tasks0/1/2 are genuinely taking involuntary timer IRQ context switches, task0 takes a checked nested preemption guard (timer IRQs remain EOI-able), allocates a new generation-tagged slot3 and validates a full 15-GPR/IRETQ trap frame on a separate private 16 KiB stack with an independently initialized legacy FXSAVE64 image. It atomically publishes the frame/ownership and only then sets slot3 Ready in the bounded 4-slot round-robin bitmap. The timer IRQ switches into and out of this previously unqueued fourth worker >=4 times; all four FX images remain distinct, worker3 progresses without yielding, marks itself Finished exactly once, and stays frozen after >=4 subsequent hardware IRQ observations. Require first-generation Blocked/Wake and task2 retirement checks, IRQ/EOI parity, exact fairness evidence and 1/4-vCPU QEMU acceptance. **This proves live admission of a NEW fourth task, NOT re-admission of the previously recycled generation2 task2, dynamic heap-backed stacks, user-mode processes, SMP scheduling or production synchronization.**

P1 in-flight task3 Blocked/Wake/Resume and terminal wake safety (under review): after task0 dynamically admits a dormant fourth stack into real BSP xAPIC IRQ round-robin, the **newly created task3 itself** moves from Ready to Blocked (without volunteering a context switch) while timer interrupts remain enabled. The next real xAPIC interrupt saves its live GPR/IRETQ frame, FXSAVE64 image and work-count snapshot; >=6 later interrupts must prove task3 never advances while omitted from the runnable bitmap, while the other original tasks continue. The timer IRQ must wake task3 **exactly once**, task3 resumes on the original stack and sees its original SSE/XMM0 state intact, and >=4 additional genuine APIC interrupt epochs verify post-wake execution before task3 can finish. Terminal task3 sets its Finished bitmap bit (not merely an owner state) and a checked wake attempt must reject resurrection. Keep original task2 terminal, quiescent recycle and second-generation direct IRETQ tests unchanged, with independent terminal bits, IRQ/EOI parity and both 1/4-vCPU QEMU. **Only isolated BSP-owned static-slot evidence; no general sleeping synchronization primitive, run-queue locking across processors or general-purpose production scheduler.**

P1 directed BSP-to-AP fixed IPI delivery proof (merged, PR #49): isolated ap-ipi-smoke QEMU flavor maps the xAPIC MMIO page uncached BEFORE APs are booted, adds a distinct external IPI vector to each AP's private IDT, and lets each secondary processor briefly enable maskable interrupts only AFTER its existing independent SMP/kernel-context tests. With 4 vCPUs, the BSP sends three individually directed fixed IPIs to each of three APs; their OWN IDT handlers issue exactly one local EOI per received interrupt and all APs park again with IF=0 before smoke exit. Zero misrouted/spurious interrupts, exact per-AP delivery parity and the prior BSP/AP test suite are mandatory. NOT x2APIC support, AP-local timer scheduling, production IRQ routing, kernel IPIs for TLB shootdown, cross-CPU task migration or an SMP preemptive scheduler.

P1 secondary-CPU local periodic xAPIC timer IRQ proof (merged, PR #50): an isolated ap-local-timer-smoke QEMU flavor reuses the BSP-created permanent uncached xAPIC alias from PR #49, established before secondary boot. Each of three APs finishes prior independent kernel-stack/GDT/IDT/TCB SMP tests, programs its OWN local periodic timer with a validated masked-first LVT/divide/initial-count plan (separate vector 0xe2), and enables IF on its own 32 KiB stack. Each AP must receive >=4 local timer IRQs and issue exactly one local EOI per delivered IRQ, demonstrate continued CPU-bound progress between IRQs, then disable IF, mask/stop its timer and repark. BSP only reads Acquire/Release evidence, never programs or acknowledges an AP timer. Four-vCPU QEMU CI enforces per-AP success, IRQ/EOI parity, zero unexpected directed IPIs, and prior smoke suites. This does **NOT** establish AP-local task preemption, calibrated production clocks, SMP run queues, migrations, x2APIC, universal hardware compatibility or TLB shootdown.

P1 three-AP independent local timer preemption proof (merged, PR #51): an isolated QEMU-only ap-smp-preempt-smoke flavor runs on four virtual CPUs and verifies THREE simultaneous secondary-CPU timer-driven schedulers, each with TWO independently owned 16 KiB kernel stacks. Each AP boots on its existing 32 KiB MP stack, finishes earlier per-CPU cooperative tests, prepares validated full 15-GPR/IRETQ frames and distinct per-task legacy x87/SSE FXSAVE64 images, and arms its OWN periodic timer (vector 0xe3). A dedicated AP assembly IRQ entry selects the other saved private stack only on that SAME AP; tasks never voluntarily yield to one another. Require >=10 genuine IRQ-triggered context switches and >=5 interrupted epochs per task per AP, both tasks' nonzero work, no stack-canary/frame or XMM0 sentinel corruption, exact per-core IRQ/EOI parity, 0 unintended directed IPIs or spurious interrupts, and each AP disabling IF, masking/stopping its timer, restoring original FX/control state and rejoining the original MP stack. BSP only verifies Acquire/Release evidence; it never runs another CPU's tasks. Full existing CI regressions remain required. **Not a production SMP scheduler**: no runnable migration, cross-core run-queue/lock semantics, user processes, XSAVE/AVX state, x2APIC, calibrated monotonic time, physical-device proof or dynamic task memory ownership.

P1 CPU-owned nested preemption guards with live AP timer deferral (merged, PR #52): build on the three independent two-task xAPIC preemption proofs, using the checked per-CPU atomic depth primitive. All three APs start with TWO nested preemption-disabled critical sections while IF remains enabled, proving >=4 genuine local timer interrupts per AP still get local EOI with ZERO task switches and zero task1 progress. Releasing only the inner guard must NOT allow a switch; after exiting the outer guard, each AP must complete >=10 IRQ-triggered switches (>=5 epochs for each worker), retain exact IRQ/EOI and SSE/FX preservation, and return with guard depth zero and IF disabled. The BSP checks >=12 total deferred IRQs and all three nested proofs. This is NOT a cross-processor lock, a dynamic scheduler critical-section API, a mechanism for IPIs/TLB shootdown or a production SMP scheduler.

P1 cross-core directed IPI remote work ownership and generational mailbox (merged, PR #53): distinct isolated ap-remote-work-smoke flavor. BSP (IF=0) creates 4 successive NEW CPU-bound jobs for each of 3 APs in CPU-owned one-slot atomic mailboxes. Each mailbox enforces monotonic generation, exact destination ownership, no overlapping publications and explicit Complete/Retire before reuse (host Rust tests include true threaded producer/consumer handoff, stale/replayed generations, duplicate IPI, wrong CPU and premature-completion denials). BSP only sends each directed fixed xAPIC IPI *after* Release publication; AP private IDT claims the slot with an atomic transition, writes exactly one local EOI and IRETQs. Actual digest computation runs only on receiving AP's original permanent MP stack, outside IRQ; BSP validates the digest via Acquire completion and retires the exact generation before publishing the next round. Require 4-vCPU QEMU proof of 12 published/sent/claimed/executed/retired jobs, 12 receiving AP-local EOIs, 0 ownership/spurious/duplicate faults, three APs parked with IF=0; retain the earlier IRQ preemption and SMP regression suite. This proves remote *new-work* execution and wake signaling only: **not migrating a live task's kernel stack/FX state**, no arbitrary dynamic runqueue, no cross-core locking for general scheduler, no Ring 3 or user processes.

P1 quiesced logical continuation transfer across APs (merged, PR #54): isolated ap-handoff-smoke QEMU mode builds on the PR #53 CPU-owned per-AP IPI mailbox. A separate one-task TaskLease model enforces a unique CPU owner and monotonically increasing migration epoch: Paused -> InTransit -> Running -> Paused; only the actual destination AP resumes it outside the IPI IRQ. Each of the 12 quanta advances a preserved logical step/digest; the current CPU must quiesce and publish an immutable Release snapshot before the BSP can transfer ownership to the next AP and signal with a directed hardware IPI. The BSP validates the independently recalculated continuation at EVERY step, denies 11 stale-owner replays, and retires the final task exactly once. Four-vCPU QEMU requires 3 APs, 11 owner transfers, 12 directed IPIs / 12 local EOIs and 12 checked logical work continuations, zero invalid/spurious IRQ, and all APs offline IF=0. Host Rust tests reject concurrent double-run, unquiesced transfer, wrong-owner, stale epoch and terminal resurrection; includes an actual threaded three-owner stress proof. **Critically this moves only quiesced logical task progress, not a saved kernel RSP, stack, GPR/FX state or process address space.** General-purpose live task migration with kernel stack lifetime, XSAVE/FPU ownership, TLS/CR3 and TLB consistency remains unimplemented.

P1 real suspended kernel RSP/FX task context across APs (merged, PR #55): isolated ap-stack-migrate-smoke QEMU-4-vCPU feature transfers the SAME live 16 KiB static kernel STACK, SAME saved System V ABI RSP (six callee-saved GPRs and return PC), SAME Rust invocation with real stack-local state, and SAME legacy x87/SSE FXSAVE64 image across 11 AP ownership changes, over 12 quanta. Every AP owns its original coordinator stack; each task is first suspended by an explicit cooperative ABI context switch with IF=0 and no AP timer armed. Only AFTER the original AP has returned to its own coordinator stack, restored its original FX state and published a verified mailbox completion may the BSP transfer the paused TaskLease owner+epoch and signal another AP with a directed fixed hardware IPI. On receipt, target AP claims within its private IDT + EOIs locally, then restores task FX and saved RSP outside IRQ, RESUMING THE ORIGINAL TASK STACK and its local Rust variables. All 12 steps preserve exact digest, XMM0 sentinel, stack canary, owner, and status; 12 IPIs/EOIs; 11 stale owner denials; all APs parked with IF=0. No live stack copying. ***This is COOPERATIVE, quiesced migration at a normal ABI call boundary, not timer-IRQ-preempted in-flight cross-core migration or a production general scheduler.*** CR3 is identical on all CPUs, no userspace, FS/GS/TLS, x2APIC, XSAVE/AVX upper lanes, arbitrary kernel locks or dynamic stack reclamation. Host tests independently validate saved RSP stack layout.

P1 real interrupt-time involuntary cross-AP task handoff (merged, PR #56): isolated ap-irq-migrate-smoke QEMU feature demonstrates one NON-YIELDING kernel task repeatedly captured by an ACTUAL AP-local hardware xAPIC timer interrupt. This is a hardware-interrupt PREEMPTED fixed-task handoff proof, still NOT a production migration scheduler: no AP-local simultaneous independent workloads under cross-core contention, dynamic stacks, arbitrary locked kernel threads, XSAVE/AVX, FS/GS/TLS, CR3 switches, Ring 3, TLB shootdown, x2APIC or physical-machine support.
